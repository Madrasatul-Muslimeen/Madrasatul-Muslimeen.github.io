## D20: plain words when a Dua save fails (J104 j104q1, audit part 103)

All four Dua saves (progress on a dua, progress on a dua's word, 🔖 Bookmark, ✓ Check this dua) said
"Not saved: " followed by the computer's own error text ("Not saved: FirebaseError: Missing or insufficient
permissions"). They now say errors.js's plain sentence in the reader's language, the same ones every other save in the
app uses: blocked by a permissions rule, signed out, could not reach the server, took too long… A failure with no
Firestore code that is a network failure ("Failed to fetch") reads as offline; anything else says the save did not go
through, with no computer text. One helper, `duaSaveFailed()` in `app/js/dua-check.js`, used by `dua-browser.js`
three times and `dua-check.js` once. These are Dua-owned files that Hadith Study's own Dua tab also uses: there, too,
a failed save now speaks plainly.

## D06: Bookmark, the Dua module's half

The 🔖 Bookmark on a Hadith-book Dua card **already writes to the same Bookmarks as Quran Study** (`saveBookmark`,
unit key `dua:<n>`, since decision 88). What it does not do yet is open the Dua page: a Dua bookmark's link is built
from `continue-strip.js`'s `MODULE_PAGES.hadith`, so it opens Hadith Study (`hadith-study.html?resume=dua:<n>`).
- **Done here (Dua-owned):** `dua-study.html?resume=dua:<n>` now opens that Dua's card (in Rasulullah Sallallahu
  A'laihi Wa Sallam's list), and the address then names its place.
- **For the MSA Architect (shared):** point a Dua bookmark (subject `dua`) and its Continue row at
  `dua-study.html?resume=dua:<n>` in `continue-strip.js` / `bookmark-nav.js` / `bookmarks.html`, if you agree. No data
  changes: the stored bookmarks stay as they are.
