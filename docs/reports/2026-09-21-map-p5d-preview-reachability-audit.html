The task asked to "remove duplicate tooling changes if already on main." tools/md2report.py is not on this bridge's protected-path table, so either keeping or dropping the change was in scope. Tested rather than assumed:

  1. Checked out PR #126's own report source (docs/reports/2026-09-20-map-p5d-note-editor-gate-b-design.md, the file whose generation PR #126 says hung).
  2. Ran main's own already-merged tools/md2report.py (PR #91's fix, confirmed present at main's tip) against it.
  3. Diffed that output against PR #126's own committed .html.

Result: they differ, and main's fix is the worse of the two — not identical, so not a duplicate. Both fixes stop the same class of infinite loop (a line satisfying neither the heading branch nor the paragraph-scanner's exclusion, so the index never advances), but by different mechanisms:

  • PR #91's fix (on main): if the paragraph scanner consumes nothing, it emits the blocking line as its own single-line paragraph and moves on. Applied to PR #126's report, the paragraph containing #117's Gate A/B matrix, and PR #120's predecessor) is split into three separate <p> tags instead of one — a real, visible rendering defect, just not a hang.
  • PR #126's fix: replaces the paragraph-scanner's bare startswith("#") exclusion with the same regex the heading branch itself uses (re.match(r'^#{1,6}\s', ...)), so the scanner only stops at an actual heading. The same paragraph regenerates as one <p>, correctly.

Recommendation: keep PR #126's md2report.py change as-is. It is not a duplicate of what's on main — it is a strict improvement on it, verified by regenerating the exact report both ways. No edit was made to PR #126's branch; nothing there needed correcting.
