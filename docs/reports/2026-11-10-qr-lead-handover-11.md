## Lessons this session
- A suite that describes a layout the Owner just asked to change is UPDATED IN PLACE with the reason in a comment (never deleted): this session did it for ~12 suites (J125, J131, J135). Always run the Word Card / Āyah card header suites against main BY NAME first; a failure the same on main is pre-existing (quran-ayah-action-sheet-browser has 2; popup-home-size 1 at 1440; quran-word-progress-rendered 3 at 360/390).
- The header bars have measured budgets (Word Card header 296 of 299px at 320px; Āyah card bar at 150–200% text). A new button needs the large-text suites (`qr-ayah-card-header-large-text-browser`, `qr-ayah-card-tiles-large-text-browser`) and the 320px width checked, and a screenshot LOOKED at.
- `display: contents` on a role="group" row gives it a zero-width rect: suites that measure the row then fail. Use a grid and `grid-column` instead.
- A pure boundary suite (`ayah-action-sheet-boundary.mjs`) enforces decision 94 (exactly ONE Note) and "aria-disabled, never native disabled": a second Note button was the first defect it found; MOVE, do not duplicate.
- A long suite run holds the shared `node serve.js` and the working tree: do not switch branches under it; run suites in the background with a summary file and a Monitor. After a worker restart `serve.js` must be started again (`node serve.js &`) and `tools/i18n-verify/node_modules` symlinked to `/opt/node-tools/node_modules` (git-ignored).
- An image the Owner sends may be the wrong one; they correct it in the next message. Ask a short tick question (AskUserQuestion) when two readings differ, then build.
- Codex review bot comments on PRs ("usage limit") and the unattended Architect's "not eligible" comments are noise: nothing to fix.
- Do not force-push; merge main into a branch instead.
